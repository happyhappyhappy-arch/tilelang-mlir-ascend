# Harness 的工程改进方向

当前能力和验证范围统一见 [能力与控制边界](capabilities.md)。本页保留跨模块的未完成工作；字段与命令分别由 [执行控制](../assets/skills/harness-resume/references/execution-control.md)、[评测入口](../assets/skills/harness-develop/references/evaluation-runner.md) 和 [升级说明](installation-upgrades.md) 定义。

## 真实设备闭环

本地 Python 入口执行冻结适配器并生成证据。通用编译器 ABI/launch 元数据导出、远端/容器执行、设备锁与逐层退出仍需具体后端。应在一个选定昇腾环境证明完整输入输出、同步/融合边界、正确性比较、正式性能样本与最终回执一致。

验收：从独立安装完成正确候选、错误候选和有效但未达性能目标的候选；精度失败跳过正式计时；初始化失败、超时和断线保留原请求并可恢复。其他执行组合逐项扩展。

## 冷启动与中断恢复

工具具有稳定事件 ID、原子账本、暂停、作业观察和历史完整性诊断。还需真实宿主会话验证：全新 agent 能仅凭 TASK/STATE 恢复、消费生成的 RESULT、解释失败并继续工作；共享环境发布与 Markdown 摘要更新中断后可以幂等补齐。

验收：启动前后、receipt 落盘、结算、接收和摘要更新等边界中断后，无重复启动、重复扣额或未确认释放；损坏历史证据定位到具体文件，不影响无关任务的读取和安全收尾。

## 计数、排名与搜索纪律

程序 control 计准入 run，AUTOMATIC 还记录宿主的独立问询/恢复等控制动作；两者目前需要协调者共同遵守。best 的合格性和可比性由程序核验，按业务权重选择更优候选仍由协调者完成。机制计划、反证与简化字段已提供，较大预算实验的强制准入和复合改动消融尚需明确触发规则。

验收：两类步数及摘要水位清楚可恢复；相同失败条件没有新依据时停止重复投入；叠加优化有可复核的保留/移除理由；最终候选在冻结输入下独立复验。

## 评测范围与隔离

当前支持逐 case mean/median latency 上限；跨比较契约的 best 迁移、更复杂统计规则和完整设备执行矩阵尚未提供。评测代码、参考、比较器与候选分别绑定，运行位于独立子进程。接收不提供恶意同账号代码的 OS 权限隔离；需要不可信候选执行时另行设计隔离后端。

## 分发与生命周期

源码安装支持清单、升级计划、中断恢复与回滚；npm/CLI、卸载、运行所需旧代码束的保存和独立发布继续按 [路线图](ROADMAP.md) 实施。开发软链接与受管副本安装分别管理，用户任务记录和机器配置保留在私有运行产物。
